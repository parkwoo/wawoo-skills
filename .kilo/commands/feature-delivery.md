# Feature Delivery

1. Read project instructions and inspect repository status; preserve unrelated changes.
2. Use `product-discovery` to establish user outcome, acceptance criteria, scope, and open decisions.
3. Use `architecture-decision` when interfaces, data, dependencies, or significant tradeoffs change.
4. Delegate implementation and apply `engineering-quality`.
5. Use `test-engineering`; add `web-experience-design` and `accessibility-audit` for UI work, and `security-review` for sensitive boundaries.
6. Run `change-readiness` and report requested outcome, implementation, evidence, unverified items, risks, rollback, and approval required.
7. Do not publish, deploy, push, tag, or perform external mutations unless explicitly approved.
