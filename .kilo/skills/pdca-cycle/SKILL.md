# PDCA Cycle

Use a short evidence loop to improve an outcome without confusing activity with progress.

## Plan

Define the problem, target users or systems, baseline, hypothesis, success metric, owner, scope, risks, and decision date. Break work into independently verifiable tasks with clear dependencies. Choose a small reversible experiment where possible.

## Do

Implement only the planned change. Record deviations, inputs, environment, and time window so results can be interpreted.

## Check

Compare the observed result with the baseline and success metric. Separate evidence from opinion. Inspect negative effects, cost, reliability, accessibility, security, and user impact where relevant.

## Act

Choose one outcome: standardize, iterate with a changed hypothesis, roll back, or stop. Capture the decision, rationale, owner, and next review point.

## Rules

- Use measurable signals where available; otherwise define a concrete qualitative acceptance test.
- Do not treat a completed task as success if the metric or acceptance test was not checked.
- Escalate before irreversible, customer-facing, financial, legal, or production-impacting actions.

## Completion criteria

Leave a concise PDCA record containing baseline, action, evidence, decision, and next step.
