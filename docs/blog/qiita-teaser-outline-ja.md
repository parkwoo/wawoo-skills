# Qiita 連載たたき台（SKU A：興味・引流）

## 位置づけ

- **読者**：個人で Cursor を使う開発者（Kilo は「ある人向け」1 段落で触れるだけ）
- **目的**：共感 → 1 コマンド or 1 ファイルで試す → Kindle / GitHub へ
- **文体**：設計書ではなく「失敗談 + 1 招」。表は 1 枚まで、長い § 番号は使わない
- **分量**：全 3 記事、**各 2,500〜4,000 字**（合計 **約 0.9〜1.2 万字**）

## 系列ブランディング

- **系列名（案）**：`Cursor で Skill が飛ばされる問題を、ファイル 1 枚で抑える`
- **タグ**：`Cursor` `AI` `MCP` `エージェント` `開発効率`
- **各記事末尾の固定 CTA**（80 字以内）  
  「仕組みと手を動かす章は Kindle『（仮題）』第 ○ 章。リポジトリは tag `v0.5.0`」

**構成（約 3,200 字）**

| ブロック | 字数 | 内容 |
|----------|------|------|
| 冒頭シーン | 400 | 同じ修正依頼で毎回手順が違う・レビューが飛ぶ |
| 原因 3 つ | 600 | 全文投入 / 選定がチャット / 完了定義なし |
| 三層 1 図 | 500 | Workflow・Skill・Agent（Mermaid 小） |
| Cursor だけの制約 | 500 | slash なし → `@.kilo/commands/...` |
| 試し：1 行 | 400 | `workflow_get` または `@feature-delivery` を開く |
| 次回予告 | 200 | 「進捗はチャットに書かない」 |
| CTA | 100 | 本 第 1 章・repo |

**コード**：0〜1 ブロック（MCP 不要でも `@file` だけで可）
