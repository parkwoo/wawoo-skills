# Research（调研）

2. **`research`**：一次情報に当たり、**事実と推測を分離**して調査結果を Markdown に残す（不確実性を捏造しない）。
3. **`product-discovery`**：ユーザー成果・受入基準・スコープ・未決事項を確定。
4. 必要に応じて **`to-spec`** / **`to-tickets`** で仕様・チケット化（**`plan-md`** で計画文書化）。
5. 報告：**証拠 / 推測 / 未検証**を区別し、意思決定と次アクションを示す。

## 注意
- 事業判断（価格・契約・法務）は**人が決める**。エージェントは選択肢と根拠を提示するに留める。
- 調査結果は `docs/` に残す場合、秘匿情報（個人情報・鍵）を含めない。
