# Documentation and Localization

Make documentation accurate, task-oriented, and consistent with the implementation.

## Workflow

1. Identify the source of truth in code, configuration, tests, or authoritative external documentation. Verify claims that can change.
2. Check audience, prerequisites, commands, paths, versions, permissions, security implications, and rollback information.
3. For localized documents, align title, metadata, headings, examples, links, claims, warnings, and calls to action. Preserve meaning rather than word order.
4. Prefer clear native phrasing over literal translation. Flag product, legal, technical, or cultural terms that should remain untranslated.
5. Check Markdown structure, link targets, code fences, and formatting after edits.
6. When public instructions reference a release, API, policy, price, or external service, distinguish verified facts from assumptions and date-sensitive information.

## Quality rules

- Do not claim a feature, performance number, compatibility guarantee, or test result without evidence.
- Keep secrets, personal data, and internal-only URLs out of public documentation.
- State known gaps rather than fabricating equivalence or completeness.

## Completion criteria

Report source evidence, files reviewed or changed, language alignment status, and unresolved factual or translation issues.
