**メイン**：個人開発のための Cursor エージェント設計 — Skill が飛ばされる問題を、ワークフローと SSOT で直す  

**サブ**：最小 MCP・ACTIVE 状態機械・テストまで（wawoo-skills 実装ベース）

## これは「一本の本」か？字数は足りるか？

| 種別 | 日本語正文の目安 | 体感 | 本たたき台での位置づけ |
|------|------------------|------|------------------------|
| 薄い Kindle 技術小冊子 | **2.5〜4 万字** | 60〜90 分 | 薄いと言われやすい（避ける） |
| **推奨：短いが中身のある技術書** | **5〜6.5 万字** | 2〜3 時間＋手を動かす | **本 SKU の目標** |
| 一般的な技術単行本 | 8〜12 万字 | 半日〜 | 今回は狙わない（冗長） |
| 入門〜運用の大型本 | 15 万字〜 | 辞典級 | kit の範囲外 |

**編集方針（結論）**

- **4 万字だけ**だと「薄い」レビューが出やすい → **5.5〜6 万字**を目標に、**事例・Checklist・付録**で厚みを出す（中身のない水増しはしない）
- 副題で **「短いが、最後まで手を動かせる」** と明示する
- Kindle 換算 **本文 120〜160 ページ相当**（コード・図多め）

**字数配分（目標 約 5.8 万字）**

| 部分 | 字数 |
|------|------|
| 本文 8 章 | 約 4.8 万 |
| 事例 2 本（第 6・7 章内） | 上記に含む |
| 付録 A〜E | 約 1.0 万 |
| **合計** | **約 5.8 万** |

→ **「一冊の技術書」としては「短編だが完結」**。O'Reilly 級の厚みではないが、**個人が週末で作り切れる 1 冊**としては十分。
